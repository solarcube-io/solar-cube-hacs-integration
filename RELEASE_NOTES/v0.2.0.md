# v0.2.0

Maintenance release from a full code review. Fixes correctness bugs in the
period meters and entry teardown, hardens the LCD bridge, cuts InfluxDB query
volume by ~13x, and adds a test suite and CI.

## ⚠️ Breaking / behaviour changes

- The third-party dashboard-card installer **stays on by default** (Solar Cube
  ships as an appliance whose users cannot install cards themselves), but every
  download is now version-pinned and it **retries on the next restart** instead
  of disabling itself after a single failure.
- **Entities are grouped under a single "Solar Cube" device** and use
  `has_entity_name`. Unique IDs are unchanged, so existing entity IDs, history
  and dashboards are preserved; some friendly names change (previously a mix of
  `Solar Cube Grid Active Power`, `SolarCube Forecasted Production 1H` and bare
  `ESS Discharged Energy`).
- **`1H` / `6H` forecast sensors now select by timestamp**, not by list index.
  The old fixed indices (3 and 23) only matched a 15-minute sample rate, and
  even then were off by one interval in both cases.
- **Lifetime kWh totals report `0` instead of `unknown`** when the source
  counter reads zero. Zero is valid at commissioning; `unknown` punched gaps
  into long-term statistics.
- **The bridge now requires an `X-Bridge-Token` header on every request.** The
  image and the integration ship with the same published default token, so
  existing deployments keep working with no configuration; override
  `BRIDGE_TOKEN` on both sides where you can. It still binds `0.0.0.0`, which
  is required for the Docker-in-Docker topology.
- The repo-root `dashboards/` copy has been removed; the packaged
  `custom_components/solar_cube/dashboards/` is now the single source of truth.
  The two had drifted apart. Nothing read the root copy.
- `Pillow` is no longer declared as a requirement (Home Assistant ships it).
  The LCD logs a clear error and stays off if it is genuinely missing.
- **The Solar LCD Bridge now lives in its own repository** at
  <https://dev.azure.com/roygard/Solar%20Cube%20(Technology)/_git/Solar_LCD_Bridge>
  (history preserved). It has a separate runtime and release cycle and does
  not belong in a HACS integration repo. The interface between the two is
  pinned in that repository's `CONTRACT.md`; each side has tests guarding its
  own half. Nothing changes for users — the shipped defaults still match.

## Fixed

- **Period meters lost the whole period on a source counter reset.** The
  baseline was rebased onto the new counter and everything accumulated earlier
  was discarded, so an inverter reset dropped `Daily PV Energy` to ~0
  mid-day. Pre-reset energy is now banked and carried forward.
- **Period meters now set `last_reset`** and restore their carried total, so
  long-term statistics handle the period rollover correctly and survive
  restarts.
- **Entry teardown never ran.** The "any entries left?" check compared against a
  dict that also held module-level bookkeeping flags, so it was always false.
  Per-entry state now lives under its own `entries` key.
- **Lovelace panel registration always failed silently.**
  `async_register_built_in_panel` is a callback, not a coroutine; the `await`
  raised `TypeError`, which was swallowed at debug level.
- **The `agents` bucket name was hard-coded** in the sensor definitions, so a
  user-configured agents bucket was ignored for 12 sensors. Definitions now
  declare a logical `source` that the coordinator resolves.
- **The options flow wiped internal one-shot markers**, because
  `async_create_entry` replaces the whole options mapping — the dashboard and
  orphan-cleanup imports re-ran on every options save.
- **A stale reload-suppression flag** could swallow the user's next genuine
  options change; it is now armed only when an update will actually fire.
- **`send_error(502, ...)` crashed the bridge handler**: the reason phrase
  contained an en dash and HTTP status lines are latin-1.
- The repairs fix flow subclassed `FlowHandler` instead of `RepairsFlow` and had
  no translations, so the confirm dialog rendered untranslated.
- The InfluxDB client is now closed when setup fails, instead of leaking a
  connection pool on every retry.
- Unknown `_field` values can no longer inject stray keys into the optimal
  actions payload.

## Security

- `hulkhaugen/hass-bha-icons` is pinned to a commit instead of tracking its
  moving default branch; every other card was already version-pinned.
- Bridge authentication is on by default via `X-Bridge-Token` (constant-time
  compare). The built-in default token is published in this repo and is
  therefore **not a secret** — it keeps unrelated services and casual probes
  off the endpoint, and the real protections remain that port 8765 is not
  published on the host and the bridge is only reachable from the Docker
  network. Override `BRIDGE_TOKEN` for genuine authentication.
- Bridge: `Content-Length` validated **before** the body is read (a client could
  previously make it allocate arbitrary memory); a malformed `Content-Length`
  no longer raises inside the handler thread.
- Bridge systemd unit runs as a dedicated `solar-lcd` user with a udev rule for
  USB access instead of `User=root`, plus standard systemd hardening.
- Compose fragment no longer publishes port 8765 on the host.
- One-shot imports (dashboard cards, Storage dashboards) only mark themselves
  done on success, so a transient failure cannot permanently break a deployment
  whose users have no way to re-trigger them.
- Flux string literals now escape `${` so a bucket name cannot open a Flux
  string interpolation.

## Performance

- **26 InfluxDB queries every 30 s → 2.** Sensor reads are batched into one
  query per (bucket, measurement, range) using `contains(...)` + `last()`.
- LCD fonts and logo are cached instead of being re-read from disk on every
  5-second refresh (13 font loads + an SVG parse + a base64 decode per tick).
- RGB565 encoding is vectorised with numpy where available (~50x faster than
  the per-pixel loop), with the pure-Python encoder kept as fallback and as the
  reference the fast path is tested against.
- Blocking filesystem calls moved off the event loop.
- Large forecast/optimal-action attribute payloads are excluded from the
  recorder.

## Changed

- Orphaned-entity cleanup runs **once per config entry** instead of on every
  startup. Unconditional pruning also discarded user renames, area assignments
  and hidden/disabled flags.
- Period-meter state is computed on coordinator updates; `native_value` is now
  a pure property.
- `iot_class` corrected to `local_polling`.
- Informational messages downgraded from `warning` to `info`.
- `.storage` backups are pruned to the newest 3.
- Removed dead code: `_async_register_dashboards` (never called, and its URL
  paths contradicted the ones actually created), `get_dashboard_files`,
  `_pil_to_rgb565_landscape`, `_draw_arrow`, `SYSTEM_OK`, and six unused colour
  constants.
- Dropped the bundled `Inter-Italic` font (904 KB shipped to every user, never
  referenced).
- Font Awesome now prefers `.ttf`/`.otf` and warns when no face loads — Pillow
  cannot always read `.woff2`. Fetch with `tools/fetch_fontawesome.sh`.

## Added

- **136 tests** in this repository (plus 17 in the bridge repo) covering the API layer, coordinator batching, period-meter
  reset/rollover/restore, horizon selection, config/options/reauth flows,
  entry setup/unload, the repairs flow and the LCD renderer, including a
  contract suite pinning the frame size, endpoint, default URL and shared
  token that the bridge depends on.
- CI: ruff, pytest with coverage, and an asset validator that checks
  translations parse and stay key-for-key in sync across languages.
- `scripts/validate_assets.py`, `tools/fetch_fontawesome.sh`, `pyproject.toml`,
  `requirements-test.txt`.
- Optional `Solar LCD Bridge token` option.
- GitHub Actions pinned to release tags instead of `@main`.
